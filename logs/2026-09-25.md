## Session 1 — Documentation reorganization



### Task

Reorganize project documentation into `docs/` and refactor server layers
to a uniform `route → controller → service → repository → json-file`
structure with centralized error handling.

### Changes

#### Docs
- Moved `ARCHITECTURE.md`, `OVERFLOW.md`, `CODE_STYLE.md`, `API.md`,
  `DATA_MODEL.md`, `LEARNING_SYSTEM.md`, `IMPLEMENTATION_PLAN.md` → `docs/`
  (git mv preserves history).
- Moved `doc/{readme,architecture,overflow}.md` →
  `docs/spec/spec-{readme,architecture,overflow}.md` with a superseded
  header on each.
- Removed `doc/` (singular); root keeps `README.md` and `logs/`.
- Updated all cross-references in README, ARCHITECTURE, IMPLEMENTATION_PLAN
  and the spec headers.
- Added `docs/CODE_STYLE.md` documenting existing conventions.

#### Server refactor
- New `server/utils/error-handler.js` — single `sendServiceError(res, err)`
  helper; dispatches by `err.code + err.status`, never by message matching.
- `json-file.js`: added `listFiles(relativeDir, regex)`; every fs access
  (including directory listing) is now confined to this module. All three
  internal throws carry `{code, status}` (`INVALID_PATH` 400,
  `FILE_NOT_FOUND` 404, `CORRUPTED_JSON_FILE` 500).
- `history.repository.js`: dropped direct `fs`/`path`; uses
  `jsonFile.listFiles`.
- `history.service.js`: removed duplicate `jsonListMonths`; added
  `assertUser` (previously enforced only at the route layer).
- `statistics.service.js`: `computeStreakDays` uses
  `historyRepository.listMonths` + `getMonthEvents` (no more direct fs).
- `content.service.js`: `progressRepository` hoisted to top-level import;
  removed inline `require()`.
- Four new thin controllers: `learning`, `history`, `statistics`, `image`.
- Rewrote `learning.routes.js`, `history.routes.js`,
  `statistics.routes.js`, `image.routes.js` to call controllers only.
- Rewrote `users.controller.js`, `quiz.controller.js`,
  `content.controller.js` to use the shared error handler; deleted their
  local `handleError` copies.
- `content.repository.js`: `assertValidType` now throws structured error.

## SQLite rewrite + frontend refactor + test infrastructure

### Summary

Three major changes:
1. Test infrastructure: Node built-in runner for API, Playwright for e2e.
2. Storage rewrite: JSON → SQLite via node:sqlite (built-in).
3. Frontend refactor: bug fixes, shared CardRender module, full i18n.

### Commits

See `git log --oneline` for the day. Key commits:
- test: add API + Playwright test infrastructure
- feat(db): replace JSON storage with SQLite via node:sqlite
- refactor(frontend): fix review.js bugs, extract CardRender, extend i18n

### Storage

- server/db/{connection,schema,import-content,init}.js
- data/app.db auto-created on boot; content imported from
  data/content/*.json only on first run.
- Repositories rewritten to SQL; no more monthly JSON history files.
- data/users.json / data/learning/ deprecated.

### Frontend

- review.js: removed .always(nextCard); added submitting guard;
  locale:changed no longer hides revealed answer.
- card-render.js: shared localizedMeaning/fromContent/fromCard.
- quiz.js: removed dead line.
- management.js: page var moved to top.
- i18n: added dashboard/history/management/quiz/userSelect groups;
  wired locale switcher into all pages.

### Tests

- API: 6 → 40+ tests covering users, content CRUD, learning,
  history, statistics, sessions, quiz.
- E2E: 2 → 6 tests covering user-select, dashboard, learn,
  review, quiz, i18n.

### Docs

- OVERFLOW.md updated for SQLite.
- ARCHITECTURE.md §16 added.
- DATA_MODEL.md adds SQL schema.
- CODE_STYLE.md notes db/connection.js as fs exception.
