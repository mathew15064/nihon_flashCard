# 2026-08-23

## Bug fix — swipe did not advance to next card

### Bug
Swipe gesture was detected visually (card followed pointer, badge showed),
but after committing, the next card never became visible — session appeared stuck.

### Root cause
`flyOut()` set `opacity: 0` on the card for the fly-out animation, but
`resetCardPosition()` only cleared `transform`/`transition` — never `opacity`.
The answer pipeline actually completed (API succeeded, `nextCard()` ran,
`renderCard()` rendered) but every subsequent card stayed fully transparent.
Two related defects in the same handler chain:
- `.always()` advanced to the next card even when the API FAILED (progress lost,
  card skipped).
- `pointercancel` was bound to the same handler as `pointerup`, so a browser
  scroll-takeover on touch could commit an unintended answer.

### Fix (public/js/flashcard.js only)
- `resetCardPosition()` now resets `opacity` as well → new card starts at translateX(0)/opacity 1.
- `handleAnswer()`: advances ONLY in the API success callback; on failure it keeps the current card, restores position, clears `answered`/`submitting`, shows error → user can retry. Removed the `.always(nextCard)`.
- Added explicit `submitting` state; guards in `handleAnswer` + `handleSwipeStart` prevent double submission / multiple API calls.
- `flyOut()` is now purely visual and calls `handleAnswer(result)` immediately (removed the `setTimeout` hop); animation cleanup is handled by reset/render.
- Separate `pointercancel` listener that only resets drag state, never answers.
- No changes to scheduler, history, schema, or API contract.

### Tests
- Swipe right/left ≥100px → review recorded, next card visible ✔
- Swipe <threshold → no answer, card returns to center ✔
- Swipe before reveal → no answer ✔
- Rapid double swipe → single POST, single advance (`submitting` guard) ✔
- Correct/Wrong buttons and Arrow keys → same pipeline, unchanged behavior ✔
- API failure (server stopped) → error shown, card stays, retry works ✔

## Changes

### Swipe gestures (learn page)
- Pointer Events based drag (touch/mouse/pen) on the flashcard.
- Swipe right ≥100px → correct; swipe left ≤ -100px → wrong; below threshold → card springs back.
- Card follows pointer with slight rotation, shows ✓ Correct / ✕ Wrong badge during drag, flies out on commit (CSS transitions only).
- Only active when card is revealed and not yet answered; duplicate submission blocked via `answered` flag; click-reveal suppressed after real drags (`dragMoved`).
- All answer paths (buttons, ArrowRight/ArrowLeft keys, Space-next, swipes) converge on `handleAnswer(result)`.
- Vertical scrolling preserved via `touch-action: pan-y`.

### i18n
- New `public/js/i18n/{en.js,vi.js,i18n.js}`: lightweight dictionary + runtime (`I18n.t`, `I18n.apply`, `I18n.setLocale`), localStorage key `locale`, default `vi`.
- Locale switcher (🇻🇳 Tiếng Việt / 🇺🇸 English) added to learn.html and review.html headers.
- Static strings moved to `data-i18n` attributes; dynamic strings use `I18n.t()`; pages re-render on `locale:changed` without reload.
- No hard-coded UI strings remain in flashcard.js / review.js.

### Vocabulary display
- learn.html/review.html back side restructured: word → reading → romanization → separator → meaning (reading/romanization lines hidden when absent).
- Frontend fallback chain for meaning: selected locale → English (`meaning`) → Vietnamese (`meaningVi`) → raw. Object-form `{vi,en}` meanings also handled.

### Data migration (additive, safe)
- Backup first: `data/backups/vocabulary.pre-i18n-2026-08-23.json`.
- Added `romanization` (hepburn) + `meaningVi` to all 15 vocabulary items.
- Verified: 15 records, all IDs unchanged, all existing fields/values preserved.

### Backend (minimal, additive)
- `server/services/content.service.js`: whitelist optional `romanization`/`meaningVi` in vocabulary validation; include them in search fields. No route/API shape changes; all endpoints backward compatible.

## Handoff

- To extend i18n to another page: include the three i18n scripts before the
  page script, add `data-i18n` attributes, replace hardcoded JS strings with
  `I18n.t()`, listen to `locale:changed` for dynamic state.
- Do not change `meaning` back to an object without updating quiz-generator,
  content.service search/validation, management.js.
- Seed scripts rewrite canonical content files — re-running them will drop
  the new vocabulary fields unless updated too.
